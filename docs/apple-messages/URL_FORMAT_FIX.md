# Apple Maps URL Format Support - Fix Summary

## Issue

Bot was unable to extract coordinates from Apple Maps URLs sent by users, causing fallback to Apple Park location with message: "We were unable to locate your nearest Apple Store"

## Root Cause

The URL parser only supported one Apple Maps URL format:
```ruby
# Only matched: ?ll=lat,lon
match = url.match(/ll=([-\d.]+),([-\d.]+)/)
```

But Apple Maps generates multiple URL formats:
- `https://maps.apple.com/?ll=37.7749,-122.4194` ✅ (original support)
- `https://maps.apple.com/place?coordinate=48.6265,2.3522` ❌ (not supported)
- `https://maps.apple.com/@51.5074,-0.1278` ❌ (not supported)

## Solution

Updated the URL parser to handle all three formats using a flexible regex:

### Before (app/services/apple_messages_for_business/apple_maps_service.rb:88)
```ruby
match = url.match(/ll=([-\d.]+),([-\d.]+)/)
```

### After (app/services/apple_messages_for_business/apple_maps_service.rb:93-94)
```ruby
match = url.match(/(?:ll|coordinate)=([-\d.]+),([-\d.]+)/) ||
        url.match(/@([-\d.]+),([-\d.]+)/)
```

**How it works:**
- First pattern: `(?:ll|coordinate)=` matches both `ll=` and `coordinate=` parameters
- Second pattern: `@` matches the at-sign format
- `||` provides fallback if first pattern doesn't match

## Additional Improvements

### Enhanced Logging (acoustic_house_bot_service.rb:867-907)

Added detailed logging at each step to help debug future issues:

**Before:**
```ruby
if coordinates
  Rails.logger.info "[Bot] 📍 Extracted coordinates..."
end
```

**After:**
```ruby
if coordinates
  Rails.logger.info "[Bot] 📍 Extracted coordinates from Apple Maps link: #{coordinates.inspect}"
else
  Rails.logger.warn "[Bot] ⚠️ Failed to extract coordinates from Apple Maps URL: #{user_message}"
end

# ... later ...

Rails.logger.info "[Bot] 🔍 Searching for Apple Stores near: #{coordinates.inspect}"

if stores.present?
  Rails.logger.info "[Bot] 🏪 Found #{stores.length} Apple Stores nearby"
else
  Rails.logger.warn "[Bot] ⚠️ Search returned 0 stores near: #{coordinates.inspect}"
end
```

**Benefits:**
- Clear visibility of each processing step
- Immediate identification of failure points
- Easier troubleshooting for users

```bash
✅ https://maps.apple.com/@51.5074,-0.1278

```
